# Q3 — Cost model + unit economics

## Assumptions

I base this model on the prod architecture proposed in Q2: `2 x m6i.large` app instances behind one ALB, `1 x m6i.xlarge` Qdrant node, `RDS PostgreSQL db.m6g.large Multi-AZ`, S3 instead of MinIO, Secrets Manager, Route 53, ACM, and CloudWatch. I intentionally keep that production footprint constant across 10 and 100 MAU so the unit-economics curve shows the real effect of fixed infrastructure dilution. The only rows that scale materially are model tokens, S3 usage, logging, and outbound transfer.

Behavior assumptions:

- `8` messages per active user per day
- `12` active days per MAU per month
- average model usage per message: `2,000` input tokens and `700` output tokens
- `0.6` RAG retrievals per message
- `50 MB` uploaded files per user per month
- `90-day` file retention in S3

For inference I assume `Claude Sonnet 4.6` on Amazon Bedrock in `eu-west-1`, priced at `$3.30 / 1M input tokens` and `$16.50 / 1M output tokens`. I add a `5%` uplift to that row to absorb embedding/indexing overhead from a cheap Bedrock embedding model, because RAG query and ingestion embeddings are immaterial relative to generation cost.

## Top 3 cost drivers at 1000 MAU

At `1000 MAU`, the economics are no longer dominated by infrastructure alone.

1. `Bedrock inference` is the largest cost by far at `$1,829.52/month`, about `71%` of total cost.
2. `Stateful data plane` is next: `RDS + Qdrant EC2 + EBS` totals about `$496.66/month`. This is the unavoidable price of keeping retrieval and relational state reliable.
3. `Stateless app and ops layer` comes third: `app EC2 + ALB + CloudWatch` totals about `$231.76/month`.

The interesting result is that S3, DNS, and secrets are almost irrelevant at this scale. The real business question is not “how do I save pennies on storage?” but “how much reasoning quality do I buy per token dollar?”

## Cost-cutting levers

`Lever 1: route standard chat to Claude 3 Haiku and keep Sonnet as an explicit premium mode.` Using current Bedrock prices, that cuts model spend at `100 MAU` from `$182.95` to about `$13.86`, taking the full monthly bill from `$889.71` to `$720.62`, a `19.0%` saving. Trade-off: noticeably weaker long-context synthesis, more manual retries on complex diligence-style prompts, and lower answer quality on multi-document reasoning.

`Lever 2: hold a “lean prod” footprint until sustained demand exceeds ~300 MAU.` Concretely: `2 x t3.large` for the app tier instead of `2 x m6i.large`, `t3.large` for Qdrant instead of `m6i.xlarge`, and `db.t4g.medium Multi-AZ` instead of `db.m6g.large Multi-AZ`. At `100 MAU`, that reduces the monthly bill from `$889.71` to about `$620.78`, a `30.2%` saving. Trade-off: less burst headroom, higher p95 latency during reindexing or peak chat periods, and lower safety margin for failover.

## Unit economics

Cost per active user per month is:

- `10 MAU`: `$71.37`
- `100 MAU`: `$8.90`
- `1000 MAU`: `$2.59`

The curve clearly breaks between roughly `80` and `120 MAU`. Below that point, the fixed production footprint overwhelms the usage-based cost. At `10 MAU`, Bedrock is only `$18.30`; almost the entire bill is the price of running production-grade infrastructure for very few users. By `1000 MAU`, the opposite is true: infrastructure is largely diluted and token spend becomes the dominant driver.

## Pricing recommendation

At `100 MAU`, monthly cost is `$889.71`, or `$8.90` per user. To earn a `50%` gross margin, the minimum fee is therefore about `$17.80/user/month` (`cost / 0.5`). I would round that up and recommend **`$19 per user per month`** as the base price.

That price is low enough to remain clearly below premium SaaS copilots, but high enough to absorb normal variance in token usage. If I expected many long, reasoning-heavy sessions, I would keep `$19` as the base seat and add a premium “deep analysis” mode priced separately, because token economics are too sensitive to let heavy users cross-subsidize everyone else.
